# 微信小程序版（uni-app）设计总结（云优先修订）

2026-11-16 v2。分支 `feat/wechat-miniprogram`，基线 `main` 24292a4。本文取代同日 v1 的“本地优先文档存储”假设：用户已确认 **数据直接上云、不存本地、个人主体、提醒走微信订阅消息、无需桌面组件、无需迁移旧程序**。决策见 [ADR0018](../adr/0018-cloud-first-wechat.md)；v1 提议见 [ADR0017](../adr/0017-wechat-mini-program.md)。

## 0. 先回答四个问题

### 0.1 数据上云，不存本地

可以，但这不是“把 SQLite 换成云文件”。小程序端不再持有完整业务状态，改为：

- **微信云开发（CloudBase）数据库** 存业务数据；
- **云函数** 做写入、校验、事务和统计聚合；
- 小程序按页面读取所需数据，内存中只保留当前页/当前会话缓存，**不写本地业务文件**；
- 断网时不能记录/查看云端数据，只能显示网络错误和重试；这是“云优先”的直接代价。

同时，产品原来的“100% 离线、数据只在设备”表述必须删除。数据在腾讯云，开发者可通过云控制台访问，**不是端到端加密**；隐私指引、用户协议、数据删除和导出必须同步重写。这是本次改动最大的产品影响。

### 0.2 个人主体能不能做 Plus

可以，但要看类目和资质。2026 年微信已向**个人主体**开放小程序虚拟支付：

- 需要个人主体、实名认证、**服务类目含“工具”**、完成小程序备案；
- 公开资料显示个人主体有月度收款限额（约 10 万元/月），费率以 MP 后台为准；
- iOS 端官方公告为 15% 优惠费率，Android/其他终端费率不同；
- 售卖“Plus 终身解锁”必须走**小程序虚拟支付**，不能引导到普通微信支付、H5、App 或个人收款码。

如果类目/备案/虚拟支付审核未通过，就只能先发免费核心版，不能伪造购买或静默解锁。

### 0.3 iOS 要不要单独申请

**不需要单独注册一个 iOS 小程序，也不需要自己向 Apple 申请“小程序合作伙伴计划”。**

- 同一个微信小程序 AppID 同时覆盖 iOS/Android；iOS 用户从微信进入，不需要另做一个 App。
- 微信官方 2026-02 公告：小程序 iOS 虚拟支付已全面支持，iOS 端享受 15% 优惠费率；由微信统一承载，不需要开发者单独和 Apple 签约。
- 但需要在 **MP 后台开通/配置虚拟支付和 iOS 商品**，并满足个人主体、类目、备案、商品审核；具体入口和费率以 MP 后台为准。
- 如果 iOS 虚拟支付未开通，iOS 可以正常使用免费功能，但不能购买 Plus；不能放外部支付链接。

### 0.4 订阅消息是不是不只有一次性

微信确实有两种，但**个人工具类小程序实际上只能用一次性订阅**：

- **一次性订阅**：用户每授权一次，开发者只能下发一条对应模板消息；用户勾选“总是保持以上选择”只是下次不再弹窗，**仍然是一条授权换一条消息**，不是长期无限发送。
- **长期订阅**：只对政务民生、医疗、交通、金融、教育、设备等少量公共/行业类目开放；普通工具/习惯类不能申请，也没有可套用的习惯提醒模板。
- **设备订阅**：需要接入硬件设备，不适用于本产品。

所以“每天 9 点自动提醒”不能靠一次性订阅可靠实现。可行的产品化只有三条路：

1. **一次性提醒**：用户点“订阅本次提醒” → 云函数到点发一条 → 用完即止；下次再授权。适合“今晚/明天提醒我一次”，不适合每日多时刻。
2. **每日摘要 + 用户每天打开**：用户每天进小程序时授权下一条，云函数定时发；用户不打开就没有下一条授权。只能算“轻提醒”，不能承诺必达。
3. **系统日历兜底**：用 `wx.addPhoneCalendar`/`addPhoneRepeatCalendar` 写系统日历副本，可重复、可闹钟；但用户明确要求走订阅消息，这会变成混合方案，需要在产品上说明。

**结论：v1 按“一次性订阅消息”设计，文案明确“本次提醒”，不做长期订阅承诺，也不伪造每日自动提醒。** 如果业务上必须每日固定提醒，需要再确认是否接受系统日历混合方案，或接受“用户每天打开才续订”的限制。

## 1. 目标与非目标

### 目标

- 微信小程序内完成 DayPanel 核心闭环：习惯（布尔/数量/次数）、频率与计划、休息、小事/常驻、手记、成就卡、统计、回顾、外观、提醒、导出。
- 数据云优先：CloudBase 数据库 + 云函数；不写本地业务数据；同一微信账号跨设备看到同一份数据。
- 个人主体可上线：类目、备案、隐私指引、虚拟支付、订阅消息按个人主体规则设计。
- 保留产品原则中仍成立的部分：无广告、无分析 SDK、无强制资料、数据可导出/可删除；不再宣称“离线/数据只在本地”。
- 视觉延续冷白、浅蓝、淡紫、暖橙、大圆角；针对小程序导航、胶囊、键盘、安全区和网络状态重新设计。

### 非目标（v1）

- 本地业务存储、离线写入、离线队列、本地数据库加密。
- Android 桌面组件、组合桌面、桌面直接打卡。
- 迁移旧 Android 数据、Loop `.db` 导入、schema12 双向兼容。
- 长期订阅消息、后台本地通知、精确闹钟、通知“稍后 10 分钟”。
- 与 Google Play 已购权益互通；两个商店是独立交易。
- iOS 原生 App/Web/桌面端；iPad/PC 不做平板双栏验收。
- 24 MB Noto Serif SC 字体打包；v1 系统字体。

## 2. 云优先的硬约束

| 约束 | 影响 | 设计应对 |
|---|---|---|
| 小程序端查询默认/最多 20 条 | 不能一次拉全量 | 页面级查询 + 分页；云函数聚合 |
| 云函数查询默认 100 条 | 统计/导出要分批 | 云函数内部分页/聚合；返回摘要 |
| 小程序链路响应上限 1 MB | 不能把完整状态返回客户端 | 只返回当前页/摘要；大导出走云存储文件 |
| 聚合可在服务端处理较多数据，但响应仍受 1 MB | 不能靠聚合绕开 | 聚合只返回小结果；原始明细分页 |
| 云函数冷启动/网络延迟 | 每次写入有延迟 | 写入显示 busy；合并高频操作；失败可重试 |
| 无本地持久化 | 断网不可用 | 明确网络错误；不做“假离线” |
| CloudBase 有免费体验期，之后计费 | 个人成本 | 控制读写次数；避免每次启动全量查询；发布前用价格计算器估算 |
| 小程序主包 2 MB/总包约 20 MB | UI/资源受限 | 分包、图标压缩、字体不进包、无重 UI 库 |

> 云开发数据库单文档上限较高，但小程序响应上限 1 MB；本设计不依赖“单文档塞下全部状态”。具体配额以 CloudBase 控制台/文档为准。

| 现有能力 | 微信替代 | 状态 | 设计与边界 |
|---|---|---|---|

| Play 购买恢复 | `openid` + 云端权益 | 受限 | 同微信账号自动恢复；不跨 Google Play/微信号 |

| AlarmManager 本地提醒 | 微信订阅消息 | 受限 | 个人工具类只有一次性订阅；一次授权一条；不能做每日本地通知 |
| 通知点击/稍后 | 订阅消息页面路径 | 受限 | 可打开指定页面；无“稍后 10 分钟”、无后台回调 |

| SAF/系统分享 | 云存储导出 + `shareFileMessage`/`showShareImageMenu` | 受限 | 导出文件由云函数生成；分享到微信/相册 |
| SoundPool/触感 | `InnerAudioContext`/`wx.vibrateShort` | 受限 | 默认关闭；失败不撤回云端写入 |
| SQLite | CloudBase 数据库 | 受限 | 云函数事务、页面级读取、服务端统计；无本地库 |
| Loop/旧数据迁移 | 不做 | 移除 | 用户已确认无需迁移 |
| 24 MB 字体 | 系统字体 | 受限 | v1 不打包；后续可 CDN 子集 |
| 系统分享目标 | 微信转发/朋友圈/收藏/下载 | 受限 | 不是任意系统 App |
| 系统主题/语言 | 小程序 darkmode + 自研 i18n | 等价偏受限 | 中英文案、日期格式自己维护 |

## 4. 总体架构

### 4.1 形态

```text
DayPanel/
├── lib/, android/                 # 现有 Flutter，保持不动
├── miniprogram/                   # 新增 uni-app 小程序
│   ├── src/
│   │   ├── pages/                 # 主包：today/tasks/journal/mine
│   │   ├── packages/              # 分包：habit/task/journal 详情/统计/卡片/设置
│   │   ├── components/
│   │   ├── stores/                # 页面级 Pinia store
│   │   ├── domain/                # 纯 TS 规则（客户端展示用）
│   │   ├── data/                  # CloudBase 客户端封装、DTO、查询
│   │   ├── platform/              # wx.cloud/wx.* 适配器
│   │   ├── i18n/ styles/ static/
│   │   └── pages.json/manifest.json
│   ├── cloud/
│   │   ├── functions/
│   │   │   ├── api/               # 读接口 + 写动作分发
│   │   │   ├── payment/           # 下单/回调/查权益
│   │   │   ├── reminder/          # 订阅任务/定时发送
│   │   │   └── export/            # 导出文件生成
│   │   └── shared/                # 与客户端共享的纯领域规则（构建时打包）
│   ├── tests/
│   └── scripts/
└── docs/
```

### 4.2 分层

- **页面/组件**：只调用 `stores`；不直接调云函数/数据库。
- **stores**：页面级状态（今日、任务、手记、统计、设置、Plus）；负责加载、busy、错误、刷新；不做业务规则复制。
- **domain**：纯 TS 规则（日期、频率、数量、卡片、统计、洞察）；客户端展示和云函数校验共用。
- **data**：CloudBase 查询/云函数调用/DTO 映射；不写本地。
- **cloud functions**：权威写入；校验 generation/revision；事务；服务端聚合；支付/订阅任务。
- **platform**：`wx.cloud`、`wx.requestSubscribeMessage`、`wx.requestVirtualPayment`、`wx.shareFileMessage`、`wx.showShareImageMenu` 等适配；测试 mock。

### 4.3 为什么不在客户端保留“全量状态”

- 小程序单次查询 20 条、响应 1 MB；全量状态会随记录增长失效。
- 跨设备/多端写入需要服务端权威 revision，客户端全量覆盖会丢更新。
- 统计/洞察/年历需要跨年数据；服务端聚合更稳。
- 代价：页面要按需加载，不能照搬 Flutter 的 `AppController` 全量内存模型；工作量增加。

## 5. 云端数据模型

### 5.1 集合

| 集合 | 文档粒度 | 说明 |
|---|---|---|
| `dp_meta` | 每用户 1 条 | schema、revision、generation、创建/更新时间；所有写动作的并发基准 |
| `dp_profile` | 每用户 1 条 | 习惯数组（含 plans）、分组、设置、外观、提醒配置；目标 <600 KB，超限拆分 |
| `dp_days` | 每用户每天 1 条 | `{day, entries:{habitId:value}}`；今日/月查询方便；避免每习惯每天一条文档 |
| `dp_tasks` | 每任务 1 条 | 一次性/常驻、计划日/完成日、归档 |
| `dp_task_days` | 每用户每天 1 条 | 常驻任务按日完成集合 |
| `dp_notes` | 每手记 1 条 | 日期、正文、关联习惯；按月分页/搜索 |
| `dp_cards` | 每天 1 条 | 成就卡、收藏、心得、完成快照 |
| `dp_activity` | 每习惯每天 1 条 | 归档履历；统计用 |
| `dp_breaks` | 每段休息 1 条 | 暂停/休假/跳过 |
| `dp_events` | 每事件 1 条 | 逐次明细；分页/统计 |
| `dp_jobs` | 每订阅任务 1 条 | 一次性订阅消息任务、发送状态 |
| `dp_orders` | 每订单 1 条 | 虚拟支付订单、状态、幂等键 |
| `dp_entitlements` | 每用户 1 条 | Plus 权益、来源订单、时间 |
| `dp_exports` | 每导出任务 1 条 | 云存储文件 ID、状态、过期时间 |

所有业务文档带 `_openid`（云函数写入时显式设置 `OPENID`）。客户端集合权限：**仅创建者可读，禁止客户端写**；所有写入走云函数。云函数从 `cloud.getWXContext().OPENID` 取身份，**绝不接受客户端传入的 openid**。

索引至少：`_openid`、`_openid+day`、`_openid+habitId+day`、`_openid+month`、`_openid+status+sendAt`、`_openid+createdAt`。

### 5.2 读取接口

| 接口 | 返回 | 说明 |
|---|---|---|
| `api.today(day)` | profile + 该日 days + 当日 tasks/task_days/card + settings | 今日页一次加载；目标 <800 KB，profile 超限拆分 |
| `api.month(month)` | 该月 days/cards + 手记分页 | 月视图；手记单独分页 |
| `api.tasks(filter)` | 任务分页 | 收件箱/今日/历史 |
| `api.journal(query, cursor)` | 手记分页 + 计数 | 月份/单日/习惯/正文交集在服务端 |
| `api.stats(range, habitId)` | 完成率/连续/数量汇总/年历摘要 | 服务端聚合，返回小结果 |
| `api.insights(range)` | 30/90/365、星期、趋势、共现、月度 | Plus；服务端计算 |
| `api.cards(month)` | 卡片分页/详情 | 卡片册 |
| `api.export(format)` | 云存储 fileID + 过期时间 | 大文件不塞响应 |
| `api.entitlement()` | Plus 状态 | 启动/前台刷新 |

读取失败/超时：显示错误 + 重试；不做本地假数据。页面 `onShow` 重新拉取当前页；跨设备写入会在下次读取时出现。

### 5.3 写入接口

统一 `api.mutate(action, payload, expectedRevision)`：

1. 取 `OPENID`；读 `dp_meta`；校验 `expectedRevision`。
2. 在云函数事务中读所需文档（profile/day/card/meta 等）。
3. 执行与客户端同源的领域规则（保存/完成/撤销/卡片/休息/计划版本）。
4. 写受影响文档；`dp_meta.revision + 1`；必要时 `generation + 1`（删除/恢复类）。
5. 返回 `{ok, revision, changed}`，不返回全量状态。

动作至少覆盖：`saveHabit`、`archiveHabit`、`deleteHabit`、`recordHabit`、`clearRecord`、`saveTask`、`completeTask`、`saveResidentRecord`、`saveNote`、`deleteNote`、`saveReminder`、`favoriteCard`、`saveReflection`、`saveSettings`、`saveBreak`、`deleteBreak`、`saveEvent`、`deleteEvent`。

删除习惯/账号涉及批量清理：云函数分页删除相关 days/events/activity 等；先隐藏/归档再清理，失败可重试；不把“部分删除”展示为完成。

### 5.4 并发与一致性

- 每次写带 `expectedRevision`；不匹配返回 `conflict`，客户端刷新后让用户重试。
- 云函数事务只覆盖一次动作涉及的少量文档；跨大量文档的删除/导出用分批任务，不做单事务全量。
- `generation` 用于删除/重建/账号级变化；旧页面写入携带旧 generation 时拒绝。
- 客户端不缓存跨会话业务数据；同会话内 Pinia 缓存可被下一次 `onShow` 覆盖。
- 云端时间统一用服务端时间；业务日期仍用用户本地日历日（客户端传 `day`，服务端校验格式/范围）。

### 5.5 数据量、成本与保留

- 每用户数据按“每日一条 days + 手记/事件/卡片”增长；CloudBase 适合这个量级，但要控制查询次数。
- 不做“每次启动拉全部历史”；统计走聚合，明细分页。
- 免费体验期后按套餐/资源点计费；发布前用 CloudBase 价格计算器估算日活/读写量。不要在未估算前承诺“永久免费云”。
- 数据保留：用户可导出/删除；账号删除要清理业务集合、订阅任务、导出文件；订单/权益按法律法规和支付对账需要保留最小记录，并在隐私指引说明。
- 不做端到端加密；如未来需要，必须重新设计查询/统计/云函数可读性，不能只在客户端加密。

## 6. 提醒：一次性订阅消息

### 6.1 规则

- 个人工具类只能申请**一次性订阅**；长期订阅不开放，不能伪造类目。
- 一次 `wx.requestSubscribeMessage` 授权 = 一条消息额度；用户勾选“总是保持”只免弹窗，不增加额度。
- 每条消息模板字段有限；标题/关键字受模板约束，不能自定义任意文案。
- 消息点击可带 `page` 路径打开小程序页面；不写完成，只导航。
- 发送由云函数调用 `cloud.openapi.subscribeMessage.send`；需要模板 ID、openid、data、page；失败码（如用户未订阅/模板参数错误）要区分。

### 6.2 任务流

```text
用户点“订阅本次提醒”
  → wx.requestSubscribeMessage({tmplIds:[T]})
  → accept：调用 api.createReminderJob(habitId, sendAt, data, page)
  → dp_jobs 存 pending（openid, templateId, sendAt, status, payload）
  → 定时云函数每分钟取 due jobs
  → subscribeMessage.send
  → success: sent；43101/无额度: invalid；其他: failed（可重试/告警）
```

- UI 必须显示“已订阅本次 / 已发送 / 已失效 / 需重新订阅”，不能只显示“提醒已开启”。
- 一个习惯多个时刻：每个时刻各需一次授权（或产品上只允许一个每日摘要时刻）。
- 任务过期/用户取消/习惯归档/删除：云函数取消 pending job；已发送不可撤回。
- 不在客户端做“定时器”，小程序切后台会被挂起。

### 6.3 产品建议

- v1 只做“今晚/明天的一次性提醒”，或“每日摘要（用户当天授权下一条）”；不承诺每日自动。
- 若必须每日固定多时刻：建议恢复系统日历混合方案（`addPhoneRepeatCalendar`），或明确接受“用户每天打开才续订”的弱提醒。
- 如果负责人不接受以上任一限制，则 v1 不做提醒，先做记录/统计，避免上线后“提醒不响”的投诉。

## 7. Plus 与虚拟支付（个人主体）

### 7.1 可行性

- 个人主体、类目含工具、实名、备案后可在 MP 后台申请虚拟支付；公开资料显示月收款限额约 10 万元，费率以后台为准。
- iOS 端微信已支持小程序虚拟支付（2026-02 公告），官方口径 15% 优惠费率；**不需要单独注册 iOS 小程序，也不需要自己向 Apple 申请**；但需在 MP 后台开通/配置 iOS 商品。
- 售卖“解锁功能/会员”必须使用小程序虚拟支付，不能外跳普通微信支付、H5、App、个人收款码。

### 7.2 商品与权益

- 一个非消耗型“Plus 终身解锁”，`short_series_goods` 道具直购；不设订阅/续费。
- 权益存 `dp_entitlements`（openid、商品、订单、状态、时间）；启动/前台恢复时刷新；同微信号跨设备恢复；不跨 Google Play、不跨微信号。
- 客户端只拿服务端签名后的支付参数；appKey/密钥只在云函数环境变量；订单回调/查单幂等，防重复发货。
- 无资质/未审核：release 不显示购买或显示“暂不可用”；debug 可用测试权益验收，但不静默解锁。

### 7.3 Plus 范围调整

无桌面组件后，Plus 不再包含“组合桌面”。剩余：

1. 逐次记录/纠错；
2. 自然周累计目标；
3. 周/月复盘长图；
4. 深度洞察；
5. 额外原创装扮。

是否保留 Plus、定价多少，需要负责人确认；如果首发不想处理支付/审核，建议 **v1 全免费、Plus 后置**，先把云数据和提醒跑稳。

## 8. 功能范围与分期

### P1 云基座与首个纵切（7–10 人日）

- uni-app CLI/TS/Vitest/包体脚本；四 tab 壳、主题、i18n 框架。
- CloudBase 环境、集合、索引、权限规则；`api.today`、`api.mutate`、`dp_meta/profile/days`。
- 领域核心（Day/数量/频率/计划）移植；客户端 store + 云函数共享规则。
- **真实纵切**：新建布尔习惯 → 完成 → 云端持久化 → 杀进程重进/换设备可见 → revision 冲突拒绝。
- 验收：typecheck、单测、云函数本地测试、构建、主包 ≤2 MB；无本地业务文件。

### P2 免费核心（15–20 人日）

- 习惯 CRUD/三种记录/历史纠正/频率/休息/分组/排序。
- 小事一次性/常驻/历史/归档/删除。
- 手记/关联/月份/搜索/删除解除关联。
- 成就卡/收藏/心得/六卡面。
- 统计/年历/时间线/单日历史（服务端聚合）。
- 外观/主题/图标/边框/字体降级；声音/触感默认关闭。
- 导出 JSON/CSV、删除数据；网络错误/重试/空态。
- 提醒：一次性订阅任务流 + `dp_jobs` + 定时云函数；状态文案。

### P3 Plus/分享（8–12 人日，可选）

- 逐次明细/纠错、周累计、复盘长图、深度洞察、额外装扮。
- 虚拟支付/权益/恢复/退款状态；iOS 商品配置。
- 卡片/海报分享、相册保存；导出文件分享。
- 若不做 Plus，本阶段只保留分享/复盘（免费或后置）。

### P4 硬化与发布（7–10 人日）

- 云函数异常/超时/重试/幂等/限流；数据删除批处理。
- 隐私指引、API 声明、备案、类目、客服/退款。
- 微信开发者工具预览/体验版/真机（iOS/Android）；弱网/断网/跨设备。
- 审核；发布说明明确一次性提醒、无桌面组件、无旧数据迁移、云端存储。

合计约 **37–52 人日（8–11 周单人）**，不含备案/资质/审核等待；比 v1 本地方案多约 25%，主要花在云函数、页面级读取、支付/订阅和云端测试。

## 9. 页面与交互

### 9.1 页面地图

主包四 tab：

- `pages/today/index`：日期条、今日习惯、周目标、休息、计划外、卡片、一次性提醒入口。
- `pages/tasks/index`：一次性/常驻、完成历史。
- `pages/journal/index`：月份/筛选/搜索、写手记。
- `pages/mine/index`：习惯、外观、提醒、订阅记录、Plus、卡片、统计、洞察、复盘、导出/删除、隐私。

分包：

- `packages/habit`：详情/编辑/管理/排序/休息/日志/单习惯统计/计划历史。
- `packages/task`：详情/历史/日期纠正。
- `packages/journal`：编辑/日期/关联。
- `packages/review`：统计/年历/时间线/单日/卡片册/卡片详情/周月复盘。
- `packages/settings`：外观/提醒/订阅记录/Plus/导出/删除/隐私/网络诊断。
- `packages/onboarding`：首次说明（云端数据、隐私、提醒限制）。

### 9.2 云优先的交互差异

- 首屏先壳后数据；加载 skeleton，不显示假数据。
- 断网：显示“需要网络”+ 重试；不清空上次页面展示（仅内存），但不允许写入。
- 写入：按钮 busy、禁止重复；成功后再更新；失败保留输入/操作并提示重试。
- 跨设备：`onShow`/下拉刷新拉当前页；冲突提示“数据已更新，请刷新后重试”。
- 提醒：区分“已授权本次/已发送/额度用完/需重新授权”；不显示“长期开启”。
- 导出：云函数生成文件 → 下载 → 分享；大文件不阻塞页面。
- 删除：二次确认；账号删除说明云端数据/订阅/权益的处理和保留范围。

### 9.3 UI 约束

- 原生 tabBar/导航栏，避开胶囊；页面栈 ≤10；`switchTab` 不传 query，用 Pinia。
- 键盘避让、底部面板、安全区；`page-container`/自定义 overlay。
- 暗色：`darkmode`/`theme.json` + 主题 class；`wx.onThemeChange`。
- 字号：rpx + 字体档；320 px/1.6 倍；48 px 点击区；`aria-label`/`aria-role`。
- 列表分页/骨架/空态；365 格热力图用 flex 行列，不用 CSS Grid 假设。
- 视觉：冷白/纸白/蓝/紫/橙/青、24 px 圆角、细边轻阴影；不打包 24 MB 字体。

## 10. 非功能设计

### 10.1 隐私与安全

- 数据在 CloudBase（腾讯云）；开发者可通过控制台/云函数访问；**不是端到端加密**。隐私指引必须如实说明。
- 身份仅 `openid`；不取头像/昵称/手机号；数据按 openid 隔离。
- 客户端读权限“仅创建者”；写权限关闭；云函数校验 OPENID，不接受客户端身份字段。
- 支付密钥/模板 ID/环境变量只在云函数；客户端不存密钥；订单/回调幂等。
- 导出文件放在私有云存储，临时 URL 过期；分享是用户主动行为。
- 删除账号：清理业务数据/订阅任务/导出文件；订单/权益最小保留并告知。
- 不做广告/分析 SDK；不把用户文本用于训练；不做公开社区。

### 10.2 性能与成本

- 页面级查询、分页、服务端聚合；避免启动全量拉取。
- 合并同日多次写入？不可以牺牲正确性；可做“完成/撤销”短时间防抖，但仍以服务端成功为准。
- 云函数冷启动：保持函数体积小、共享依赖打包、按需拆分；高频读尽量客户端直读 DB。
- 监控：云函数错误率、P95、DB 读写次数、导出失败；发布前估算免费额度耗尽后的成本。
- 包体：主包 ≤1.6 MB 目标/2 MB 硬限；图标压缩；字体不进包；统计/设置进分包。

### 10.3 国际化/日期

- 端口 `app_en.arb`/`app_zh.arb`（约 734 key）到 `src/i18n`；脚本检查 key 一致。
- 日期：本地日历日 `YYYY-MM-DD`；服务端只校验，不按 UTC 反推；星期/月格式自研。
- 数量：整数千分位、最多 3 位小数；拒绝负数/科学计数/超长。
- 文案去掉“离线/本地/桌面组件/系统通知”，改为“云端/一次性服务通知/导出”。

### 10.4 可测试性

- 领域纯函数 + 固定时钟/ID；客户端和服务端共用测试夹具。
- 云函数单测：mock `wx-server-sdk` 数据库/事务；覆盖 revision 冲突、卡片事务、删除、订阅任务状态。
- 安全规则测试：控制台/测试用例验证不能读他人、不能客户端写。
- 页面组件测试：表单/空态/网络错误/提醒授权拒绝。
- 真机：弱网/断网/跨设备/支付沙箱/订阅真实模板/相册/分享。

服务器（2C4G）只做：

以及云函数本地 Node 单测/打包检查；不跑微信开发者工具、真机、支付真实交易、CloudBase 控制台审核。

- 支付：沙箱下单/取消/失败/恢复/退款；iOS 商品；个人主体后台配置。

## 12. 风险与待确认

| 风险/决策 | 影响 | 建议 |
|---|---|---|
| 数据上云改变隐私定位 | 原“离线/数据只在设备”卖点消失 | 重写隐私/介绍；接受腾讯云与开发者可访问；不做 E2E |
| 断网不可用 | 地铁/弱网体验 | 明确网络提示；不做假离线；后续可选只读缓存（需重新定义“不存本地”） |
| 一次性订阅限制 | 每日提醒不可保证 | 只做“本次提醒”；或系统日历混合；或砍提醒 |
| 个人虚拟支付审核 | Plus 能否收费 | 先确认类目含工具/备案；不通过则免费版 |
| iOS 费用/配置 | 定价与审核 | MP 后台确认 15%；iOS 价格可单独设置 |
| 月度收款限额 | 大额销售受限 | 个人阶段接受；后续升级主体 |
| CloudBase 成本 | 免费期后费用 | 发布前估算；控制查询；监控 |
| 云函数延迟/冷启动 | 写入等待 | busy/重试；函数瘦身；关键读客户端直读 |
| 1 MB 响应/20 条查询 | 大历史/导出 | 分页/聚合/云存储导出 |
| 数据删除批处理 | 删除不彻底/超时 | 分批任务+状态；可重试；告知 |
| 微信审核/备案 | 上线时间 | 预留 2–4 周；先体验版 |
| 品牌/GPL/插画 | 发布许可 | 发布前审查 |

需要负责人确认：

1. 是否接受“云端数据 + 断网不可用 + 开发者可访问”的隐私定位变化。
2. 提醒：只做一次性“本次提醒”，还是接受系统日历混合，还是 v1 不做提醒。
3. Plus：v1 是否收费；若收费，是否接受个人虚拟支付审核/费率/月度限额；若不收费，Plus 功能是否全免费或后置。
4. 是否保留导出 JSON/CSV 和删除账号（建议保留；不做旧程序导入）。
5. 小程序类目选择（工具-效率/生活服务等）与备案主体资料。
6. 小程序名称/品牌/插画/GPL 发布边界。

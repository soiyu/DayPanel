## 阶段顺序

1. **P0 设计确认**：负责人确认支付主体、提醒降级、桌面组件降级、Loop 迁移、品牌/许可。
2. **P1 基座**：WM01–WM06。首个纵切必须真实落盘；不做“先搭全部页面再补存储”。
3. **P2 免费核心**：WM07–WM17。每完成一个域，补对应单测和真实重开/失败路径。
4. **P3 微信/Plus**：WM18–WM21。支付与订阅必须先有服务端签名/权益状态机，再写 UI。
5. **P4 发布**：WM22–WM25。外部资质/审核等待单独记录，不混入开发“完成”。

## 工程约束

- 2C4G 服务器：只跑 `pnpm typecheck`、`pnpm test`、`pnpm build:mp-weixin`、`pnpm audit:size`；串行、限量；不跑微信 IDE、模拟器、Flutter 全量构建、图片处理。
- 不提交 `dist/`、`node_modules/`、AppID 私密配置、支付密钥、真实用户备份。
- 每批代码：typecheck + 相关 Vitest + 构建 + 包体审计 + `git diff --check`；真机项在 STATUS/台账记录具体设备与缺失。
- 不在小程序端伪造 Android 能力：桌面组件、后台本地通知、Loop 直导、系统分享目标都不做假入口。
- 备份 schema12 是跨端契约；任何字段变更先写 ADR 并同时评估 Android 兼容。

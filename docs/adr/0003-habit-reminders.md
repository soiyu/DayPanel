# ADR 0003：FL11 习惯提醒

2026-11-06。用户要求下一批任务，完成后不关机。本批交付 FL11；常驻小事/日志仍是后续任务。

- 每个习惯可保存 1–5 个互不重复的本地时刻，启停不删除时刻；配置保存在 SQLite v3 的 reminders 表，有 revision。时刻按用户当前时区解释。
- Android AlarmManager + 非导出 Receiver，冷进程不依赖 Dart 常驻。Receiver 以只读 SQLite 一致快照核对 habit、计划、当日记录、周目标、世代和 revision；不从通知直接写用户库。
- 每日/星期/间隔按当日计划触发；周目标未达标且当日未达标时提醒。今日记录达标、周目标达标、归档/删除/关闭提醒后，取消对应已发布通知和待触发事件。
- 每个习惯只注册下一次触发，不做有限天数后停止的预排列表。触发后安排下一次。开机、包更新、时间/时区变化、授权精确闹钟，以及前台恢复时重排。只安排未来事件；不补发关机/权限关闭期间错过的提醒。
- 标准提醒使用 setAndAllowWhileIdle，可能受系统节电延迟。可选 SCHEDULE_EXACT_ALARM 仅在用户主动进入系统页时申请；有授权用 setExactAndAllowWhileIdle，无授权/撤销时安全回落标准模式。不使用 USE_EXACT_ALARM、全屏 Intent 或电池白名单权限。
- 通知权限只在用户主动启用/保存提醒时请求（API 33+）。系统总开关、频道、精确权限状态在提醒中心明确展示，权限拒绝保留配置，返回 App 后重查并重排。声音/震动由系统频道设置管理。
- 通知只有去记录/稍后10分钟。去记录使用直接 Activity PendingIntent，数量打开现有快记页、布尔进入详情，之后用户确认写入。跨日/恢复/关闭后的旧入口拒绝；不把通知点击等同完成。
- 稍后动作一次有效，只接受仍有效的已发布通知实例；不跨午夜。多个时刻共享每习惯一条通知，最新通知替换旧通知；一次触发可延迟，过期日期不补发。实例 token + 已投递键保护重复广播/重复稍后；同一天夏令时回拨不重复发同一时刻。
- 启动/写入/恢复后同步原生调度；调度失败不能误报数据保存失败，配置仍在库里，界面单列系统未接入提示。备份升级到 schema3，兼容 schema2 文件（无提醒），恢复前副本同样兼容；系统权限与已投递/稍后运行态不进入备份。
- 原生运行态使用设备本地 SharedPreferences，数据世代变化清空。Flutter 内所有成功数据操作后同步；用户强行停止 App 后 Android 会阻止闹钟，需重新打开，不宣称可绕过系统强停/厂商后台限制。
- 测试需覆盖 Dart 存储/升级/备份、纯 Kotlin 日期/计划/DST、原生通知/延迟/取消/权限及系统事件。设备证据明确区分 API28 与 API33+，不足项不计为全设备验收。

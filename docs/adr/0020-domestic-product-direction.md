# ADR0020：国内化产品方向（微信小程序）

2026-11-17。当前 `feat/wechat-miniprogram` 已把 Android/Google 功能换成微信能力，但产品假设仍偏海外：商店分发、一次性买断、桌面组件、系统通知、离线隐私、无社交、英文优先。本 ADR 确定“国内行情”方向，先设计，不直接实现争议功能。

关联：[国内功能设计](../product/DOMESTIC-FEATURES.md)。

状态：提议，待确认社交、微信运动、长辈模式、服务号与商业化边界。

## 决策

1. **中文优先、微信原生**
   - 默认简体中文；英文保留但非首发重点。
   - 微信 `openid` 隐式身份 + CloudBase 云端同步；不引入独立账号密码。
   - 分享、提醒、支付、广告都按微信生态规则设计，不照搬 Google Play。

2. **中国日历是 P0**
   - 内置年度法定节假日/调休表（国务院办公厅通知），云端可修正。
   - 习惯计划支持 `any` / `workdays` / `restdays` / `skip_holidays`。
   - 休息日不进统计分母、不打断连续、不发提醒；调休补班按工作日。
   - 农历/节气只做展示与主题，不参与打卡分母。

3. **补记是 P0，但不伪造事实**
   - 允许过去 7 天（可配置到 30 天）补记，明确标“补记”，记录真实写入时间。
   - 补记可计入完成事实/连续，但不自动补发“当天卡片”；不做付费补签卡、复活卡、押金。
   - 未来日期仍禁止；历史计划仍按当时版本。

4. **长辈模式是 P0**
   - 大字号、强对比、简化今日页、一键打卡；不改变数据。
   - 不做语音输入，避免额外录音/识别隐私。

5. **社交与微信运动默认关闭、需单独确认**
   - 轻分享/群打卡：只分享完成状态/周报，不分享手记正文；默认关闭；不做公开广场/排行榜/诱导分享；未成年人默认关闭。
   - 微信运动步数：`scope.werun` 授权，服务端解密，仅存每日步数快照；默认关闭，可删除；不做医疗建议。
   - 在负责人确认前，不把社交/步数写进实现范围。

6. **商业化：v1 仍全免费**
   - v1 不接广告；达到 100 UV 后评估流量主。
   - 后续如需付费，用微信虚拟支付；不自动续费；不做“看广告解锁核心”。
   - 广告不进入打卡确认、删除、隐私、提醒授权等关键路径。

7. **合规**
   - 小程序备案、隐私指引、未成年人说明、删除入口必须保留。
   - 不做医疗/治疗/疗效宣称；步数、血压等只做记录。
   - 既有“不提供整库导出/客服”决定保留，但隐私页必须说明删除方式；如审核要求联系方式，用 MP 主体信息，不新增客服入口。

## 后果

- `HabitPlan`、日记录、统计、提醒、卡片、年历都要接入中国日历；数据模型需要迁移。
- 补记需要审计字段，连续/卡片规则要重新定义并测试。
- 长辈模式需要单独的页面密度/字号/入口策略，不是简单放大字体。
- 社交/微信运动会引入新的隐私、云函数解密、审核和删除范围；默认不做，避免范围失控。
- 广告/虚拟支付前必须完成备案、隐私更新和主体资质。

## 未决

- 轻社交/群打卡是否进入 v1.1；若做，需要群组数据模型和隐私文案。
- 微信运动是否做；需验证 CloudBase 解密能力。
- 补记范围与是否计入连续/卡片。
- 长辈模式入口与默认触发条件。
- 是否升级企业主体以使用服务号长期提醒。
- 广告上线时点与广告位。
- 无导出/客服在合规与国内用户预期下是否保持；建议至少保留删除和隐私联系方式。

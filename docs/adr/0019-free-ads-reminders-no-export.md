# ADR0019：v1 全免费、后续广告、三通道提醒、不提供导出但提供注销

2026-11-16。用户明确：提醒需要“一次性本次提醒 + 每日摘要续订 + 系统日历混合”，三通道默认全开；v1 不收费、功能全免费，后续用广告赚钱；个人设置提供“注销账号”按钮；不提供客服和副本导出。

本 ADR 修订 [ADR0018](0018-cloud-first-wechat.md) 的 Plus/虚拟支付部分；云优先、个人主体、一次性订阅限制、无桌面组件、无旧程序迁移仍有效。ADR0017/0018 保留历史记录。

状态：提议。注销批处理时限、三通道默认时刻和广告开通时点待确认。

## 决策

1. **v1 全免费，不做 Plus/虚拟支付**
   - 所有现有高级能力（逐次明细、周累计、复盘长图、深度洞察、额外装扮）在 v1 免费开放。
   - 删除 Plus 页、购买/恢复/待支付状态、`dp_orders`/`dp_entitlements`、支付云函数、iOS 商品配置。
   - 不申请个人虚拟支付；不涉及 iOS 15% 费率、月度收款限额、退款/对账。
   - 未来若恢复收费，另写 ADR，不能把广告和付费混成未披露的强制路径。

2. **后续广告变现，v1 不接广告**
   - 先以全免费产品验证留存；达到微信流量主条件后再评估接入。
   - 流量主公开条件为小程序累计独立访客（UV）达到 100 人及以上（以平台最新规则为准）；个人主体可申请，审核以平台为准。
   - 广告形态以后台可用为准：Banner、插屏、激励视频、视频、原生模板、封面等；分成比例以平台为准（公开资料曾为 50%）。
   - 广告不得诱导点击、遮挡主操作、伪装成内容、在记录/隐私/支付页面强制插屏；不加“看广告才能用核心功能”的墙。
   - 接入广告前必须更新隐私指引/用户告知（广告 SDK/平台可能收集设备与行为信息），并重新评估审核；v1 代码只预留 `AdSlot` 组件/开关，不加载广告 SDK。
   - 广告收入不改变“数据可访问/可纠正”的承诺；但广告上线后原“零广告”品牌表述必须删除。

3. **三通道提醒并存，默认全开**
   - **一次性本次提醒**：用户点订阅 → 一次授权一条 → 云函数到点发送；适合临时/单次。
   - **每日摘要续订**：用户当天授权下一条摘要；云函数在设定时刻发送“今日待打卡摘要”；用户不打开/不续订就没有下一条。不是长期订阅。
   - **系统日历混合**：用 `wx.addPhoneRepeatCalendar`/`wx.addPhoneCalendar` 写系统日历副本，可重复/可闹钟；用户需授权 `scope.addPhoneCalendar`，系统确认；不提供程序化更新/删除已写事件。
   - 设置默认三通道全开；但“默认开”不等于“已授权”：摘要首次/每日要用户点授权，日历首次要系统授权，一次性每次要用户点订阅。
   - 为避免同一时刻重复轰炸：默认建议日历按习惯时刻、摘要固定在 21:00、一次性只在用户主动订阅时创建；UI 显示三通道实际状态并允许单独关闭。
   - 同时开启仍可能重复，UI 必须警告；用户可关闭任一通道。
   - 个人工具类没有长期订阅；每日摘要仍是一次性授权，不能承诺必达。
   - 日历副本是设备本地状态，不存云端；换机/恢复后需重写；文案明确“副本”。

4. **不提供导出，提供个人设置注销账号**
   - v1 不做整库导出 JSON/CSV，不提供客服数据副本；成就卡/海报分享图片不算整库导出。
   - 单条记录/习惯/手记/小事的删除仍是核心功能；这里的“注销”指删除该 openid 下全部云端业务数据和提醒任务。
   - 个人设置提供**“注销账号”**按钮：二次确认 + 输入确认词；说明不可恢复、日历副本需自行删除、待发订阅任务取消、已发送消息不可撤回。
   - 云函数 `deleteAccount` 按 openid 分批删除全部业务集合、`dp_jobs`、临时文件；全部成功后才显示完成并回到首次引导。部分失败必须显示“注销未完成”并可重试，不能假装成功。
   - 注销后同一微信 openid 再进入是空数据；旧数据不可恢复（无导出/无客服副本）。
   - 注销满足“删除”权利；**不提供副本仍存在个人信息可携带/复制权的合规风险**，按负责人决定接受并在隐私页说明。
   - 隐私页说明数据在云端、保留期限、开发者可访问、非端到端加密，以及注销入口；不提供客服/邮箱工单。

5. **验证边界**
   - 服务器只做 typecheck、Vitest、云函数本地测试/打包、构建、包体审计；不跑微信 IDE/真机/广告/审核。
   - 三通道提醒、日历厂商差异、注销批处理、流量主开通、广告审核都必须真机/后台验证。

## 后果

- 收入路径从“一次性买断”变为“先免费、后广告”；短期无收入，云成本需自担；广告上线受 100 UV、审核、隐私更新约束。
- 三通道默认全开会增加授权弹窗、重复提醒和设置复杂度；默认建议“日历按习惯时刻、摘要 21:00、一次性按需”，但仍需用户授权。
- 注销是自助的，删除请求运营成本低；但无导出/无副本会削弱数据可携带性，存在合规风险，按负责人决定接受。
- 全免费后 Plus 锁定态/购买页/权益判断全部移除，UI 与测试减少；但未来若恢复收费，需要重新设计。
- 云优先、无本地、断网不可用的约束不变。

## 未决

- 注销批处理在云函数时限内无法一次完成时的分页/续跑方案；部分失败如何阻止用户误以为已注销。
- 三通道默认时刻：日历按习惯时刻、摘要 21:00 是否合适；一次性入口放在哪里。
- 广告接入时点：首发不接；达到 100 UV 后接哪些形态、放在哪些页面。
- 不提供副本的风险接受方式（隐私页如何表述，不承诺“可下载副本”）。
- 广告上线后是否保留“无个性化广告”选项/说明（以微信广告能力为准）。

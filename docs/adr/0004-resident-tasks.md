# ADR 0004：常驻小事与完成历史

2026-11-06，执行 FL12。用户要求继续开发；本轮保持开机。

- 常驻小事是可重复使用的事项，不是按频率生成新任务的 recurrence。仅用户主动选择“常驻”创建，普通小事不转换、不自动重生。
- 常驻事项保持在小事页独立区域，每个当地日最多一条完成记录，今天完成后仍保留在原区域。次日查看为未记录，昨天完成保留；未做的日子不生成数据、欠账、逾期、失败或 streak。
- 新建类型选项清楚说明“一次性/常驻”；类型创建后固定，避免旧历史被重新解释。常驻不设截止日；开始日为实际创建日，不能记录未来或创建前。允许在详情指定日期补记/纠正，仅改变该日期。
- 归档隐藏常驻项但保留记录，取消归档再次可用；归档期间禁止写记录。永久删除需确认，级联删除其完成历史。改名不改变过去的日期或完成事实。
- SQLite v4：原 tasks 表增加 resident/start_day/archived，旧任务默认一次性，原字段值不动。独立 task_entries 保存 task_id/day 唯一键。普通任务继续原 completed_day；常驻 completed_day/due_day 均为空，不能混用两个写入入口。
- 完成历史按日期汇总单次已完成任务与常驻日记录，最近七日回顾合计“小事完成”，不混入习惯统计。普通任务重开会移除其当前完成事实，常驻纠正只移除当天记录。本轮不引入操作审计日志。
- 备份 schema4 包含新字段/常驻记录，严格验证类型、引用、唯一键与日期范围；兼容 schema2/3（补默认一次性字段）。恢复/回退、数据世代与提醒同步保持原行为。Android 提醒只读取兼容的 v3/v4 习惯表，不因本次升级停调度。
- UI：新建底部面板提供两种小事类型；小事页常驻独立区，普通任务仍分组；历史与归档是明确入口。详情可查看/纠正日记录、归档/删除。动作只写显式目标值，跨午夜旧按钮拒绝当日操作并提示刷新。
- 本规则是 DayPanel 对公开“常驻小事”的明确设计，不宣称小日常未公开的细项已逐项实测还原。

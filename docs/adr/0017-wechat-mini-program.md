# ADR0017：微信小程序第二客户端与 Google 能力替换

2026-11-16。基线 `main` 24292a4。用户要求在独立分支把 Google Play 安卓版实现为微信小程序，Google/Android 能力替换为微信生态；本轮先完成设计总结，不开始功能实现。

状态：提议，待负责人确认支付主体、提醒降级和发布范围后实施。

## 背景

现有产品是 Flutter/Android 单一客户端：SQLite v12、本地备份 schema12、Android 桌面组件、AlarmManager 提醒、系统日历、SAF 文件、系统分享、Google Play 一次性买断。产品原则是离线优先、无广告、无分析、无强制账号、无云同步。微信小程序运行在完全不同的运行时：没有 SQLite、没有后台常驻、没有桌面组件、没有 Google Play，文件、通知、支付、分享和身份都必须使用微信/宿主能力。

把 Flutter 代码直接编译成小程序不可行。可行路线是保留 Flutter 客户端，另建 uni-app（Vue 3 + TypeScript）小程序客户端，共享业务规则和备份契约，不共享 UI 代码。

## 决策

1. **独立第二客户端**：在仓库新增 `miniprogram/`，使用 uni-app Vue 3 + Vite + TypeScript + Pinia；不改 Flutter 的 `lib/`、`android/` 运行时代码，不把小程序代码塞进 Flutter 工程。两个客户端共用备份 schema12 和领域规则，不共用 Flutter Widget。
2. **本地优先文档存储**：小程序端不引入 SQLite，也不把习惯数据放到云数据库。使用与备份表同形的 JSON 文档、双槽原子写入、SHA-256 完整性校验、generation/revision 和恢复前副本；业务数据仍只存在用户设备。
3. **Google 能力替换**：
   - Google Play 一次性买断 → 微信小程序虚拟支付 + 服务端按 `openid` 记录权益；不得用普通微信支付卖虚拟解锁，不得外跳支付。
   - Android 桌面组件 → 小程序没有公开的可编程桌面组件 API；降级为应用内“组合面板”，桌面快捷方式/浮窗只作为用户手动入口。
   - AlarmManager/本地通知 → 系统日历副本（`wx.addPhoneCalendar`/`wx.addPhoneRepeatCalendar`）为主；不做后台本地通知，不伪造准时能力。一次性订阅消息只作为后续可选增强，不作为 v1 默认。
   - SAF/系统分享 → `wx.chooseMessageFile`、`wx.shareFileMessage`、`wx.showShareImageMenu`、相册保存。
   - SoundPool/触感 → `InnerAudioContext`/`wx.vibrateShort`。
   - Android 日历 `ACTION_INSERT` → 微信系统日历 API，语义仍是“用户确认的独立副本”，不是双向同步。
4. **Plus 范围不变**：基础记录、备份/恢复/导出、已存数据查看/纠正保持免费；组合面板、逐次明细、自然周累计、复盘海报、深度洞察、额外装扮仍作为 Plus 权益。若支付主体/类目/虚拟支付未就绪，则先发免费核心版，不伪造购买、不静默解锁。
5. **迁移路径**：Android 用户先导出 schema12 JSON 备份，再在小程序导入；小程序导出的 JSON 必须能被 Android 恢复。Loop `.db` 导入不迁到小程序端，由 Android 客户端完成 Loop 导入后再导出 JSON。
6. **不进入 v1**：iOS/web/桌面端、云同步、账号体系、广告/分析、AI、专注计时、Loop DB 解析、后台闹钟、与 Google Play 权益互通。
7. **验证边界**：服务器只做 TypeScript 检查、Vitest、构建和包体审计；微信开发者工具、真机、日历、分享、支付沙箱和审核必须在有图形界面的设备上完成。不得用“构建通过”代替真机/平台验收。

## 后果

- 小程序需要重写 UI 和平台适配层；领域规则可逐条移植并有测试保护。
- 桌面组件、后台提醒、Loop 导入三项能力会明确降级；产品文案和商店/小程序介绍不得暗示这些能力存在。
- Plus 需要额外的最小服务端（建议微信云开发）保存 `openid`、订单和权益，不保存习惯内容；隐私指引和客服/退款流程必须同步。
- 小程序发布受主体、备案、类目、隐私指引、虚拟支付资质和 Apple 15% 分成等平台规则约束；这些是外部前置条件，不能由代码绕过。
- 备份 schema12 成为两个客户端之间唯一可靠的数据契约，必须做双向兼容测试。

## 未决

- 主体是个人、个体户还是企业；是否具备/愿意申请虚拟支付和商户资质。
- Plus 在小程序是否首发收费；若收费，iOS 端是否开通 Apple 小程序合作伙伴计划。
- 用户是否接受“系统日历副本”替代本地通知；若不接受，是否接受一次性订阅消息的逐次授权和最小云函数。
- 品牌名、图标、插画与 GPLv3 在微信平台的发布/许可边界。

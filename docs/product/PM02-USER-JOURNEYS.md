# PM02 用户路径与运营体验审查

2026-11-08，基线 `215f026`。用户要求从运营、实际使用和产品经理视角继续审查。本文是评审结果与后续实施建议，**所列问题尚未在本批修复**；PM01已有的修复不回滚。产品保持免费、离线、Android、无账号/广告/分析SDK。旧原生工程未修改。

## 判断方法与证据

继续采用 Product Manager Toolkit 的用户任务、价值/成本、MoSCoW 与可验证验收方法。按首次建立、日常记录、回看、休息后继续、数据保留五条旅程审查真实路由、默认值、空态和失败恢复。范围包括习惯/数量、一次性和常驻小事、手记、统计、卡片、提醒、桌面组件、设置/外观与备份恢复。没有用户规模、使用频次或留存数据，因此不编造RICE分数和转化率，不把假设写成已观察到的流失原因。

证据分两类：

- **流程复现**：内存SQLite + 实际Flutter Widget导航，4个诊断案例确认新建不可见、筛选空态主动作不匹配、搜索草稿丢失。通过表示问题被复现，不表示修复或新功能验收。
- **代码确认**：依据下表列出的当前实现确认入口/分支存在；对认知成本、留存和运营效果的解释属于产品判断，尚无真实用户研究支持。

## 产品应帮助用户完成什么

| 时刻 | 用户要完成的事 | 运营应该支持的结果 | 适合出现的信息 |
|---|---|---|---|
| 第一次打开 | 先建一项适合自己的事，并真实记一次 | 第一次成功记录；只建立列表还没体验核心价值 | 少量易理解的模板、可改的安排、保存后的明确落点 |
| 日常打开/桌面 | 找到当前想记的事，迅速完成 | 不用反复找入口、算总量含义或处理管理选项 | 今天状态、直接记录、明确保存反馈 |
| 临时做了/漏记了 | 找到正确事项和日期，把事实补全 | 不为额外记录重新建事项或改计划 | 计划外记录入口、日期承接、保存确认 |
| 想看进展/找旧文字 | 从一个日期或关键词找到真实内容 | 能看清过去，再决定继续或调整 | 可点的日期、有效搜索范围、适用的统计 |
| 中断后回来/换机 | 继续使用，知道原数据和安排在哪里 | 恢复掌控感、避免误操作和数据丢失 | 今天入口、明确休息状态、本机导出状态与恢复后下一步 |

原则：将“成功做完用户自己的事”作为体验目标。打开次数、强制连续签到、为了领奖加任务、重复弹权限、分享拉新均不作为本项目的优化方向。已有首页直接完成、数量确认、休息不算失败、已获卡保留、默认安静和严格恢复保护应继续保留。

## 如何验证对用户有用

以下是拟验收目标，不是已测出的转化率或耗时：

1. 在昨天或不匹配筛选中添加喝水，保存后能明确看到新增项，并以一个主动作去记录；不靠新建第二个同名项找到它。
2. 筛选无结果一次操作清除筛选；无计划日能找到已有事项；普通计划外记录不要求改计划。
3. 查过去休假能看懂当日状态，没有无法完成的解除指引；今天恢复仍保持历史数据。
4. 搜索本月没有的旧月文字，一次操作扩大月份且关键词不丢。
5. 点击回顾中的前天直接进入前天明细；从历史明细进入统计保留约定日期范围。
6. 未来事项很多时常驻仍能就近记录；当天已做和未做都清晰，不产生无记录日欠账。
7. 导出取消、失败、成功状态区分；只成功才更新本机导出时间；恢复后检查提醒/组件为可选，旧动作仍失效。

先用固定任务、内存数据、真实Launcher/设备和中英文/窄屏/大字号检查完成率、步骤、返回、取消与错误恢复。这里的“完成率”是验收任务能否完成，不是线上留存统计。可后续征求真实使用反馈，但不恢复外部五人走查作为开工门槛，不加分析SDK、不收集隐性数据。

## 平台建议核对

2026-11-08核对Android官方文档，仅支持J11的平台可行性与权限时机，不作为本App已经实现的证据：

- [AppWidgetManager](https://developer.android.com/reference/android/appwidget/AppWidgetManager)：`isRequestPinAppWidgetSupported`与`requestPinAppWidget`。支持取决于Launcher；请求返回true不等于已添加；取消可能无回调；系统此路径不会自动打开provider配置页，必须设计自己的配置和真实widgetId绑定。不得在确认前落成虚假的组件实例。
- [通知权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)：在用户理解用途并主动启用相关功能时请求，不能让拒绝权限阻断正常记录。

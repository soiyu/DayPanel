# 国内行情功能设计（微信小程序）

2026-11-17。分支 `feat/wechat-miniprogram`。本文针对“微信小程序 + 国内用户”重做产品假设，不把海外版功能原样搬运。实现前需负责人确认社交、微信运动、长辈模式和商业化边界。

关联：[微信小程序设计](../design/WECHAT-MINIPROGRAM.md)、[国内化 ADR](../adr/0020-domestic-product-direction.md)。

## 0. 结论

当前版本是“微信外壳 + 海外习惯 App 假设”：Google Play 买断、Android 桌面组件、系统通知、离线隐私、无账号、英文优先、无社交。国内用户的实际预期更接近：

- 微信里直接用、微信账号自动同步；
- 中国节假日/调休要能识别，别在放假时催打卡；
- 漏打卡要能补记，但不要制造焦虑；
- 提醒要能持续，不能只靠“每次授权一条”；
- 分享/小程序码/群/朋友圈是主要增长路径；
- 长辈/大字号/简单模式是真实需求；
- 免费+广告或低价会员比一次性买断更常见；
- 数据在腾讯云、要备案、要隐私指引、要能删除；
- 不要“国外那种极简冷淡”，要更温暖、有节日感、有中文语境。

## 1. 海外假设 vs 国内现实

| 领域 | 当前海外式假设 | 国内设计 |
|---|---|---|
| 分发 | Google Play 商店 | 微信小程序码、群、朋友圈、公众号/服务号 |
| 身份 | 无账号 | 微信 `openid` 隐式身份；可选头像昵称只用于分享 |
| 付费 | Google Play 一次性买断 | v1 全免费；后续流量主广告/虚拟支付（需主体资质） |
| 设备能力 | Android 桌面组件/本地通知 | 小程序浮窗/桌面快捷方式；订阅消息/系统日历；无桌面组件 |
| 隐私 | 100% 离线、数据只在设备 | 云端存储、跨设备同步；断网不可用；隐私指引必须改 |
| 日历 | 周一/星期/间隔 | 中国法定节假日、调休补班、工作日/休息日、农历/节气（可选） |
| 记录 | 未来/开始日前禁止；历史纠正 | 保留边界，但增加“补记”语义；不伪造历史计划 |
| 激励 | 连续/成就卡，低压 | 连续/补卡/挑战/轻社交；仍不做惩罚、押金、抽卡 |
| 提醒 | 本地 AlarmManager | 一次性订阅/每日摘要/系统日历；长期服务号需企业主体 |
| 内容 | 英文优先、极简 | 中文优先、节日/节气主题、温暖插画、长辈模式 |
| 合规 | Google Play Data Safety | 小程序备案、隐私指引、未成年人、广告标识、删除请求 |
| 获客 | 商店 ASO | 分享海报/小程序码/群/朋友圈；不做诱导分享 |

## 2. 国内用户的真实任务

### 2.1 上班族

- 早起、喝水、久坐起身、背单词、运动、阅读。
- 工作日节奏强，周末/节假日节奏不同；调休上班日容易被忽略。
- 漏打卡常见，需要补记但不想被“断签”羞辱。
- 提醒要能到微信服务通知；日历副本可接受，但不能每次手动。

### 2.2 学生/备考

- 每日学习时长/题量/单词数；周目标；考试周弹性。
- 需要“补记”与“周/月复盘”，不需要社交压力。
- 不适合做“自习室/专注计时”（当前明确排除）。

### 2.3 家庭/长辈

- 吃药、喝水、散步、量血压？**不能做医疗建议**；只做记录/提醒。
- 大字号、强对比、少层级、一步完成。
- 子女代设置？涉及账号/隐私，v1 不做共享账号。

## 3. 国内功能地图（优先级）

### P0 必须做（国内可用性）

1. **中国节假日/调休日历**
   - 法定节假日、调休补班、工作日/休息日标记。
   - 习惯可设置“法定节假日跳过/只在工作日/周末”。
   - 统计分母排除休息日；提醒不在休息日骚扰。
2. **补记（补卡）**
   - 允许过去 7/30 天补记，明确标注“补记”；不伪造当时计划。
   - 连续/成就卡规则要写清；不能把补记包装成“当时完成”。
3. **长辈模式**
   - 大字号、强对比、简化今日页、隐藏次要入口；一键打卡。
4. **中文优先的分享/海报**
   - 小程序码、群/朋友圈分享；默认脱敏；不诱导分享。
5. **合规**
   - 小程序备案、隐私指引、未成年人说明、广告标识（后续）、删除入口。

### P1 建议做（留存/增长）

6. **微信运动步数**
   - 用户授权后读取每日步数，自动填充“步数习惯”；可关闭。
   - 需要服务端解密/云函数；不宣称医疗/健康建议。
7. **21 天/100 天单人挑战**
   - 自选习惯、周期、目标；只做进度卡，不做押金/奖金/抽奖。
   - 挑战期间允许补记，但标注；不制造“断签惩罚”。
8. **轻分享/群打卡**
   - 分享今日卡片/周报到群；朋友可“鼓励”或“围观”，不暴露手记正文。
   - 可选邀请码/小组；默认关闭，不做排行榜/公开广场。
9. **节气/节日主题**
   - 24 节气/春节/中秋等卡面/主题；原创资源；不做迷信/运势。
10. **订阅消息体验优化**
    - 一次性“今晚提醒我”、每日摘要续订、系统日历混合；文案明确限制。

### P2 商业化/规模化

11. **流量主广告**
    - 达到 100 UV 后接入；非核心路径；不遮挡、不诱导、不看广告解锁核心功能。
12. **微信虚拟支付（如需付费）**
    - 个人主体类目含工具可申请；iOS 15% 优惠费率；月限额/资质以后台为准。
    - v1 不做；广告优先。
13. **服务号长期提醒（如升级企业主体）**
    - 服务号模板消息可做更稳定提醒；需用户关注、企业主体、模板审核。
    - 个人主体 v1 不做承诺。
14. **家庭/情侣共享（谨慎）**
    - 只共享完成状态/鼓励，不共享手记；需独立数据模型和隐私设计。

## 4. 重点功能设计

### 4.1 中国节假日/调休

**数据**

```text
dp_calendar (year, days: [
  { day, kind: 'workday'|'weekend'|'holiday'|'makeup_workday', name? }
])
```

- 每年国务院办公厅通知发布后更新；内置当年 + 下一年，云端可下发修正。
- 不依赖第三方接口；避免节假日数据缺失导致误判。
- 农历/节气单独做展示层，不参与打卡分母（除非用户明确选择）。

**习惯计划**

在 `HabitPlan` 增加：

```text
calendarRule: 'any'|'workdays'|'restdays'|'skip_holidays'
```

- `workdays`：只在工作日（含调休补班）出现。
- `restdays`：只在周末/法定假日出现。
- `skip_holidays`：原计划在法定假日自动休息，不催、不计失败。
- 调休补班按“工作日”处理，不能按星期几简单判断。

**统计/提醒/卡片**

- 休息日不进入分母、不打断连续、不发提醒。
- 成就卡只按“当天应做且完成”发；休息日不补发。
- 年度日历显示“休/班/节”标签，避免用户误判。

**UI**

- 今日页日期条显示“周三 · 工作日/中秋/调休上班”。
- 习惯编辑增加“节假日规则”。
- 年历增加节假日颜色/图例。

### 4.2 补记（补卡）

- 入口：今日页“补记昨天/选择日期”；习惯详情历史。
- 范围：默认 7 天，设置中可开 30 天；未来仍禁止。
- 写入字段：`recorded_at`（真实写入时间）、`for_day`（业务日期）、`backfilled=true`。
- 语言：显示“补记”，不显示“当天完成”。
- 连续/卡片：
  - 补记可以计入“完成事实”，但不伪造“当天获得卡片”；
  - 连续天数可计入，但详情标注“含补记”；
  - 不提供“补签卡”道具，不做付费补签。
- 审计：用户可查看“何时补记”；删除/纠正同样记录。
- 与国内习惯 App 的“补卡”对齐，但不做惩罚/复活卡。

### 4.3 微信运动步数

- 入口：设置 → 数据来源 → 微信运动；默认关闭。
- `wx.getWeRunData` 需要用户授权 `scope.werun`；返回加密数据，服务端/云函数解密（需验证当前 CloudBase 能力）。
- 每天只存一个步数快照（不存原始轨迹）；用于“步数习惯”自动填充。
- 用户可关闭/删除步数数据；不向第三方共享；不宣称医疗效果。
- 失败/无数据不伪造 0；显示“未获取”。

### 4.4 21 天/100 天挑战

- 单人挑战：选择习惯、周期、目标（例如每天/每周 N 天）。
- 进度 = 已完成/应做；补记标注；休息日不计失败。
- 完成发一张挑战卡；不做奖金、押金、抽奖、排行榜。
- 分享只展示挑战名称/进度，不展示手记。
- 可随时退出，退出保留已产生记录。

### 4.5 轻分享/群打卡

- 默认只分享“今日完成 N 项/周报”，不分享手记正文/习惯敏感名称。
- 分享卡片带小程序码；朋友打开是只读海报/落地页，不是公开主页。
- 群打卡：可选邀请码加入小组；小组只看完成天数/鼓励，不看正文；默认关闭。
- 不做公开广场、排行榜、附近的人、诱导分享。
- 未成年人默认关闭社交功能。

### 4.6 长辈模式

- 今日页：只保留日期、习惯大卡、完成按钮；隐藏统计/卡片/分享。
- 字号 ≥ 1.3 倍，按钮 ≥ 56px，强对比；支持系统字体缩放。
- 文案更直白；减少英文/术语。
- 可与正常模式切换，不改变数据。
- 不做语音输入（需要额外识别服务/隐私）。

### 4.7 节气/节日内容

- 24 节气、春节、中秋、端午、重阳等主题卡面/配色。
- 原创插画/矢量；不复制竞品。
- 不做运势、迷信、医疗建议。
- 节气内容可作为分享海报模板，不做信息流。

### 4.8 提醒/服务号

- 个人主体：一次性订阅 + 每日摘要 + 系统日历；不承诺长期。
- 企业主体：可评估服务号模板消息/长期订阅；需用户关注、模板审核、隐私说明。
- 国内用户预期“每天固定提醒”，必须用文案管理预期；不能伪造。
- 休息日/节假日按计划跳过。

### 4.9 商业化

- v1 全免费，不接广告；达到 100 UV 后评估流量主。
- 广告位：我的/统计底部/复盘结果页；不在打卡确认、删除、隐私、提醒授权弹窗插屏；不做激励视频解锁核心。
- 后续如需付费：微信虚拟支付；个人主体类目含工具可申请；iOS 15% 优惠费率；不做订阅自动续费。
- 不用“补签卡/复活卡/抽奖”做付费点。

### 4.10 合规

- 小程序备案、隐私保护指引、用户协议、未成年人说明。
- 数据在腾讯云；开发者可访问；非端到端加密；提供删除入口。
- 不提供整库导出/客服（按既有决定）；隐私页需说明限制和删除方式。
- 广告上线后更新隐私指引/广告标识；不做个性化推荐承诺。
- 不做医疗/诊断/疗效宣称；步数/血压等只做记录。

## 5. 数据模型影响

新增/调整（云优先，无本地）：

```text
dp_calendar             # 年度中国日历（节假日/调休）
dp_step_days            # 每日微信运动步数快照（可选）
dp_challenges           # 单人挑战
dp_challenge_days       # 挑战每日进度/补记标记
dp_groups / dp_group_members  # 仅当确认轻社交
```

`HabitPlan` 增加 `calendarRule`；`RecordEvent`/日记录增加 `backfilled`、`recordedAt`（或单独审计集合）。

所有新增能力仍需：

- 客户端只读自己的数据；
- 写入走云函数 + revision；
- 删除账号时一并清理；
- 无本地业务数据。

## 6. 页面调整

- 今日：节日/调休标签、补记入口、长辈模式大卡。
- 习惯编辑：节假日规则。
- 年历：节假日/调休图例。
- 我的：数据来源（微信运动）、挑战、长辈模式、分享设置。
- 新增：挑战页、群组页（如确认）、微信运动授权说明。
- 分享海报：中文模板、小程序码、隐私默认。

## 8. 需要确认

1. **轻社交/群打卡**是否做？此前产品明确排除社交；国内增长很依赖它，但会增加隐私/审核/数据模型成本。
2. **微信运动步数**是否做？需要 `scope.werun` 授权和服务端解密验证。
3. **补记范围**：7 天/30 天/不限；补记是否计入连续/卡片。
4. **长辈模式**是否 v1 必做；范围多大。
5. **节假日规则**默认值：法定假日自动跳过，还是用户逐个选择？
6. **服务号/长期提醒**是否需要；个人主体做不到，需企业主体。
7. **商业化**：v1 免费+后续广告，还是后续低价会员；广告位接受哪些页面。
8. **农历/节气**是否只做展示，不做提醒/统计。
9. 现有“无导出/无客服”在国内合规/用户预期下是否保持；建议至少保留删除入口和隐私联系方式。

## 用户任务与问题

负责人要记录喝水时，本应关注日期、已记录总量、目标/单位和输入确认，却进入兼有休假、空日志、提醒、计划版本、归档与删除的通用大详情页。功能数量替代了场景设计。另一类缺陷是有逻辑但展示不适用：周目标先展示日完成率、无日义务仍提示解锁卡、历史详情悄悄回今天。

验收目标：完成一次数量记录无需处理日志/休假/计划履历；历史日期在路由中不丢；纯周目标只显示适用考核；没有当日日义务不显示无法达成的领奖承诺；已有内容通过明确管理入口仍可找到。目标用工程行为和设备步骤验证，不使用新增分析SDK。

## 全功能处置矩阵

| 范围 | 当前用途与问题 | 本轮决定 |
|---|---|---|
| 每日/布尔习惯 | 当天是否完成，有明确主动作 | 保留完成/取消；记录与整项设置分层 |
| 数量习惯（喝水、页数、步数等） | 记录当前累计总量；原大摘要和快捷值容易被误认为加一次 | 压缩摘要，输入为中心，明确替换累计总量；保存前显示将改成多少；不引入自动累加 |
| 历史记录/纠正 | 进入详情丢失首页所选日期 | 明确传initialDay；按该日计划/单位，历史只改所选日 |
| 习惯详情 | 把所有能力连续堆在一起 | 默认只处理所选日记录；历史/统计次级，设置独立页 |
| 暂停/休假 | 管理现在及未来的整体安排，混在历史日上下文中 | 归入习惯设置，明确从今天或未来开始；休息记录仍保留 |
| 单日跳过 | 已计划而当天无需做；无安排日出现跳过没有意义 | 普通无安排日不显示；每周目标跳过需说明整周考核影响 |
| 关联手记 | 可用于读书心得、运动感受等；不是每次喝水必填 | 进入设置中的可选记录入口，已有手记计数可达，取消强制空卡展示 |
| 提醒 | 全习惯设置，非某次饮水内容 | 放入习惯设置/提醒中心，归档时不提供可用错觉；权限路径保留 |
| 计划版本 | 解释历史目标，不是打卡时的选择 | 设置中按需展开，明天生效提示靠近编辑字段 |
| 类型/分组/图标/边框 | 不可变类型假装可选、编辑页全选项展开 | 已有类型只读；整理/装扮次级展开；目标单位频率不隐藏 |
| 一次性小事 | 完成后保留实际完成日；列表与历史标题路径不同 | 标题统一详情，编辑为明确入口，完成/重开保留 |
| 常驻小事 | 按需今天做过一次，默认却强调纠正历史 | 默认今天状态/操作，历史次级；不会变成重复任务或欠账 |
| 事项删除/恢复后的旧页 | 缺失对象返回白屏/旧对象风险 | 明确失效说明与返回；旧generation不允许继续写 |
| 独立手记/搜索/月浏览 | 有真实文本查找需求 | 保留正文优先及组合筛选；不自动完成“写日记”习惯 |
| 数量统计 | 用户先关心实际量，趋势却排在完成率后面 | 数量/单位趋势优先，日/周考核按范围内历史计划条件呈现 |
| 周目标统计 | 纯周目标展示无意义日完成率/0连续 | 依据范围历史计划判断适用项；混合日→周范围两类都保留 |
| 年历/跨类型时间线 | 回看真实记录，不是今日待办 | 保留独立回顾入口，日期明确、未知历史不作失败 |
| 七日回顾与详细统计 | 有部分入口重叠但功能层次不同 | 保留概览/明细；不为本次审查做无证据的大导航迁移 |
| 成就卡/收藏/心得 | 可选回顾激励，空义务仍显示领奖提示 | 没有可计入日义务且无已得卡时隐藏提示；已得卡永远保留 |
| 图片分享 | 用户主动导出，隐私可控 | 保留默认隐藏名称/心得、摘录不改原文、系统选择器；无自动发送 |
| 常用模板 | 降低建立成本，但默认值不能成为通用处方 | 保留可编辑目标；早餐时段明确早晨，植物/力量频率由用户调整；不重写已有事项 |
| 桌面组件 | 无界面完成/取消、数量输入是近期已验证能力 | 保留显式目标和generation/revision/ABA，详情日期传递修复；帮助入口明确是添加说明 |
| 外观/语言/反馈 | 可选个人偏好，已支持预览取消 | 保留，不能影响业务目标；不借审查新增装饰选项 |
| 文件备份/恢复/旧库导入 | 数据保护与迁移，复杂确认有实际必要 | 保留严格预览/确认/事务回退，不为“简单”删保护步骤 |
| 账号/云/付费/分析/专注 | 产品已明确排除 | 不新增 |

## 本轮优先级与边界

必须修：日期漂移、记录/设置混杂、类型/状态不适用项、纯周目标错误展示、无义务领奖误导、旧页空态与generation。应修：常驻今天/历史分层、总量替换说明、已有类型只读、量化趋势前置。后续：七日概览与详细统计总导航是否合并、真正逐杯饮水事件。后续需新的用户意图/数据，不用假测试效果承诺。

不按习惯名称或图标判定“这个人不需要写日志/休假”。这些能力可能合理，改的是所在层级和默认展示；原有用户数据、历史计划、卡片与关联文字全部保留。无数据库/备份版本变化（SQLite10/schema10）。

本轮实施结果：矩阵内必须/应修项均已实现并作限定验证。后续仍保留七日概览导航是否合并、逐杯事件记录、厂商真机与真实TalkBack。补充清理：旧库迁移/未知历史说明仅在实际历史未知时显示，归档/休息只读记录保留0与未记录的区别。具体命令、测试数量、设备截图与APK哈希见STATUS的PM01条目。
